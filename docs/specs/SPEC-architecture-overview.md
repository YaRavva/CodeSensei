# Обзор архитектурных решений платформы (CodeSensei)

## 1. Общая архитектура (Tech Stack)

Платформа CodeSensei построена на современном технологическом стеке:
- **Фронтенд и бэкенд**: Next.js 16 (App Router, React Server Components, Turbopack).
- **Интерфейс и стили**: Tailwind CSS, shadcn/ui компоненты, Lucide React иконки.
- **Редактор кода**: `@monaco-editor/react`.
- **Клиентское выполнение Python**: **Pyodide** (WebAssembly), позволяющий выполнять Python-код непосредственно в браузере пользователя без нагрузки на бэкенд-сервер.
- **Бэкенд-сервисы и база данных**: **Self-hosted Appwrite 1.9.x** (Auth, TablesDB базы данных для модулей, задач, попыток, достижений и профилей).
- **Хостинг и деплой**: Appwrite Sites ( SSR-адаптер Next.js в контейнерах OpenRuntimes).
- **ИИ-интеграция**: Omniroute AI API для генерации задач, подсказок и помощи.

## 2. Ключевые архитектурные компоненты

### 2.1. Система авторизации и сессий
- Сессии управляются через серверные cookie Appwrite.
- Реализована проверка сессии на сервере (`getCurrentAccount()`, `getAuthContext()`) с защитой приватных маршрутов через middleware и серверные компоненты.
- Поддерживается OAuth-авторизация через Google и GitHub с обработкой callback-маршрутов на бэкенде.

### 2.2. Исполнение и проверка кода (Test Runner)
- Код ученика выполняется в изолированной среде Pyodide в браузере.
- Для задач с функциями (`def`) тест-раннер инжектирует параметры из `testCase.input`.
- Для линейных процедурных задач тест-раннер внедряет входные данные в глобальное пространство видимости и проверяет переменную `result` (или `output`).

### 2.3. Структура данных (TablesDB)
- **Modules (модули)**: Содержат название, описание/теорию, тему (`topic`), уровень (`level`) и статус публикации (`is_published`).
- **Tasks (задачи)**: Содержат связи с модулем (`module_id`), стартовый код (`starter_code`), эталонное решение (`solution_code`), тестовые кейсы (`test_cases`), подсказки (`hints`) и критерии оценки (`rubric`).
- **User Progress & Attempts**: Фиксация успешности решений, начисленного опыта (XP) и достижений.

### 2.4. Принципы развертывания (Appwrite Sites Deploy)
- Деплой на самохостинг Appwrite Sites выполняется с помощью легкого стейджинга исходного кода (~220 КБ без `node_modules` и `.next`), что исключает ошибки превышения размера файлов и гарантирует стабильную сборку в OpenRuntimes (`npm run build`).
- Переменные окружения для продакшн-окружения настраиваются через защищенные переменные сайта (Site Variables) в панели Appwrite.
- Все изменения платформы документируются в графе спецификаций (Spec Graph).
