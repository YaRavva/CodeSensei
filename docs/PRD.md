# Product Requirements Document (PRD)
## CodeSensei - Интерактивный Python-тренажер для школьников

**Версия:** 1.0  
**Дата:** 2025  
**Статус:** Утверждено

---

## 1. Общие сведения

### 1.1 Название проекта
CodeSensei

### 1.2 Цель проекта
Создание интерактивного Python-тренажера для школьников с геймификацией, персонализацией и модульной системой обучения.

### 1.3 Целевая аудитория
**Основная аудитория:** Школьники 7-9 классов (14-16 лет), изучающие Python по стандартной программе.

**Дополнительная аудитория:**
- Учителя информатики (создание и управление контентом)
- Администраторы системы

---

## 2. Технический стек

### Frontend
- **Framework:** Next.js 14+ (App Router)
- **Язык:** TypeScript
- **UI библиотека:** React
- **Стилизация:** shadcn + Tailwind CSS
- **Редактор кода:** Monaco Editor

### Выполнение кода
- **Технология:** Pyodide (WebAssembly в браузере)
- **Безопасность:** Web Workers, timeout механизм

### Backend & База данных
- **Хостинг:** Appwrite Sites (Self-hosted Appwrite SSR Node.js)
- **База данных:** Appwrite Databases
- **Аутентификация:** Appwrite Auth

### ИИ-сервисы
- **Провайдер:** Hugging Face Inference API
- **Модель:** openai/gpt-oss-20b
- **Использование:** Генерация контента и AI-подсказки

- **Методы:** Email/Password или Magic Link (Supabase Auth)

## 4. Функциональные требования: Администратор (Учитель)

### 4.1 Панель Администратора

#### Доступ
- Защищенный маршрут в Next.js
- Доступ только пользователям с ролью `teacher` или `admin` (настраивается в Supabase RLS)
- Проверка прав доступа на сервере

#### Управление Модулями
**CRUD-операции:**
- **Создание модуля:**
  - Название
  - Описание
  - Тема (например, "Переменные", "Циклы", "Функции")
  - Уровень сложности (1-5, определяется учителем)
  - Порядок отображения
  - Статус публикации

- **Редактирование модуля:**
  - Изменение всех полей
  - Управление уроками внутри модуля

- **Удаление модуля:**
  - Мягкое удаление (is_published = false)
  - Или полное удаление с предупреждением о потере данных

#### Управление контентом модуля
**Операции:**
- Редактирование теории модуля (Markdown/HTML)
- Генерация/управление заданиями, привязанными к модулю
- Порядок отображения задач в модуле

#### Управление Заданиями
**CRUD-операции для заданий:**
- Создание/редактирование задания (привязка к `module`)
- Название и описание
- Стартовый код (starter_code)
- Тестовые случаи (формат JSON, см. раздел 5.3)
- Рубрика и промпт для AI-оценки (eval_prompt, rubric)
- Подсказки (предзаготовленные)
- XP награда
- Сложность (easy/medium/hard, наследуется от модуля или переопределяется)

### 4.2 Конструктор Контента с ИИ-помощником

#### Генерация Теории/Заданий

**Процесс генерации:**
1. **Форма ввода:**
   - Тема модуля
   - Уровень сложности (базовый/средний/продвинутый)
   - Целевой класс (7-9)
   - Предыдущие изученные темы (опционально)

2. **Генерация контента:**
   - Кнопка "Сгенерировать теорию ИИ"
   - Кнопка "Сгенерировать задание ИИ"
   - Отправка запроса на Vercel API → Hugging Face Inference API
   - Использование промптов из `IMPROVED_AI_PROMPTS.md`

3. **Модерация и редактирование:**
   - ⚠️ **Обязательное утверждение учителем перед публикацией**
   - Предпросмотр сгенерированного контента
   - Редактирование всех полей
   - Валидация контента (синтаксис кода, структура JSON)
   - Кнопка "Опубликовать" после проверки

4. **Хранение:**
   - Сгенерированный контент сохраняется как черновик
   - Статус: `draft` → `pending_review` → `published`
   - История изменений (опционально)

## 5. Технические требования

### 5.1 Безопасность

#### Выполнение кода
- **Локация:** Исключительно на стороне клиента через Pyodide (Wasm)
- **Защита от злонамеренного кода:**
  - Timeout выполнения: 5-10 секунд
  - Ограничение использования памяти
  - Web Workers для изоляции выполнения
  - Запрет на использование системных функций (файлы, сеть)

#### Доступ к данным
- **Row Level Security (RLS):** Реализация в Supabase
- **Политики безопасности:**
  - Студенты могут видеть только опубликованные модули
  - Студенты могут видеть только свой прогресс
  - Только админы/учителя могут редактировать контент
  - См. примеры в `DATABASE_SCHEMA.md`

#### API Keys
- Хранение ключа Hugging Face API в переменных окружения Vercel
- Использование бэкенд-маршрутов для проксирования запросов
- Ключ не должен быть виден на фронтенде

---

### 5.2 Интеграция Pyodide

#### Оптимизация загрузки
- **Lazy loading:** Загружать Pyodide только на странице с заданием
- **Индикатор загрузки:** Прогресс-бар при первой загрузке
- **Кэширование:** Использовать browser cache для Pyodide
- **Размер:** ~8-10 MB (информировать пользователя о загрузке)

#### Тестирование кода
- Использование стандартной библиотеки Python (unittest)
- Изоляция выполнения тестов
- Парсинг результатов для отображения в UI
- Формат результатов: JSON с детализацией каждого теста

---

### 5.3 Формат тестовых случаев

**Структура JSON:**
```json
[
  {
    "id": "test_1",
    "description": "Базовый случай с положительными числами",
    "input": {
      "a": 5,
      "b": 3
    },
    "expected_output": 8,
    "category": "basic",
    "is_visible": true
  },
  {
    "id": "test_2",
    "description": "Граничный случай с отрицательными числами",
    "input": {
      "a": -5,
      "b": -3
    },
    "expected_output": -8,
    "category": "edge",
    "is_visible": false
  }
]
```

**Правила:**
- `input` всегда объект JSON с именованными параметрами
- Имена параметров должны соответствовать параметрам функции
- `expected_output` может быть любого типа (number, string, boolean, array, object)
- `is_visible`: видимые тесты показываются ученику, невидимые - только для проверки
- `category`: "basic", "edge", "error" (для статистики)

**Пример преобразования для Python:**
```python
# Код ученика
def add(a, b):
    return a + b

# Генерируемый код для теста
test_input = {"a": 5, "b": 3}
result = add(**test_input)  # Распаковка словаря
assert result == 8
```

### 5.4 Интеграция ИИ

#### Модель и API
- **Модель:** openai/gpt-oss-20b
- **Endpoint:** Hugging Face Inference API
- **Проксирование:** Через Vercel API routes
- **Лимит провайдера:** до 300 запросов в час на проект

#### Промпты
- Использование улучшенных промптов из `IMPROVED_AI_PROMPTS.md`
- Задания содержат rubric и eval_prompt для детерминированной AI-оценки
- Структурированные JSON ответы
- Валидация ответов перед сохранением

#### Rate Limiting
- **Провайдер:** Глобальный предел 300 запросов/час
- **Студенты:** 5 AI-подсказок в день (пер-пользователь)
- **Учителя:** 20 генераций контента в день (пер-пользователь)
- **Оценка решений:** батчинг/дедупликация и кэширование по хэшу кода и версии задания
- **Очередь и деградация:** очереди с backoff; fallback на локальные тесты при исчерпании квоты
- Кэширование одинаковых запросов
- Fallback на предзаготовленные подсказки при недоступности API

#### Эндпоинты AI-оценки
- `POST /api/tasks/evaluate` — серверная AI-оценка попытки: вход `task_id`, `code`, `runtime_output`; выход `ai_score`, `ai_feedback`, `passed`; сохраняет попытку

## 6. Система геймификации (XP и достижения)

### 6.1 Начисление XP

#### Базовые значения
- **Easy задачи:** 10 XP
- **Medium задачи:** 20 XP
- **Hard задачи:** 30 XP

#### Множители
- **Первая попытка (успешная):** 1.0x (полное значение)
- **Вторая попытка (успешная):** 0.7x (70% от базового)
- **Третья и последующие попытки:** 0.5x (50% от базового)
- **С использованием AI-подсказки:** 0.5x (50% от базового)

#### Бонусы
- **Бонус "Идеальное решение":** +5 XP (решение с первой попытки без ошибок)
- **Бонус "Без подсказок":** +3 XP (решение без использования AI-подсказок)
- **Бонус "Скорость":** +2 XP (решение быстрее среднего времени для задачи)

**Итого максимально:** Базовое значение × 1.0 + 5 + 3 + 2 = базовое + 10 XP

#### Пример расчета
Задача medium (20 XP), решена с первой попытки без подсказок за короткое время:
- Базовая награда: 20 XP
- Множитель первой попытки: 1.0x = 20 XP
- Бонус идеальное решение: +5 XP
- Бонус без подсказок: +3 XP
- Бонус скорость: +2 XP
- **Итого: 30 XP**

## 14. Ограничения и допущения

### Технические ограничения
- Pyodide поддерживает не все библиотеки Python
- Выполнение кода ограничено браузерными возможностями
- Размер загружаемого Pyodide (~8-10 MB)

### Бизнес-ограничения
- Бесплатный тариф Hugging Face API имеет rate limits
- Supabase free tier имеет ограничения на количество запросов

### Допущения
- Пользователи имеют современные браузеры с поддержкой WebAssembly
- Стабильное интернет-соединение для загрузки Pyodide
- Базовое знание Python не требуется (обучение с нуля)
