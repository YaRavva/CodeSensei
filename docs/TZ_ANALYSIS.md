# Анализ ТЗ проекта CodeSensei

## Общая оценка
ТЗ достаточно структурированное и покрывает основные аспекты проекта. Однако есть несколько критических моментов, которые требуют уточнения и улучшения.

---

## 🔴 Критические проблемы и риски

### 1. PyScript/Pyodide - Производительность и ограничения
**Проблема:**
- Размер Pyodide ~8-10 MB (не сжатый)
- Первая загрузка может занимать 5-15 секунд на медленном соединении
- Не все библиотеки Python доступны в Pyodide
- Выполнение кода может быть медленнее, чем нативным Python

**Рекомендации:**
- ✅ Добавить индикатор загрузки Pyodide при первом запуске
- ✅ Рассмотреть lazy loading (загружать Pyodide только на странице с заданием)
- ✅ Добавить прогресс-бар загрузки Pyodide
- ✅ Указать список поддерживаемых библиотек в документации
- ✅ Рассмотреть fallback на серверное выполнение (через Appwrite Functions с ограничениями) как опцию для сложных задач

### 2. Безопасность выполнения кода
**Проблема:**
- Хотя код выполняется на клиенте, нужно защититься от:
  - Бесконечных циклов (может "заморозить" вкладку браузера)
  - Чрезмерного использования памяти
  - Злонамеренного кода (например, `while True: pass`)

**Рекомендации:**
- ✅ Добавить timeout для выполнения кода (например, 5-10 секунд)
- ✅ Ограничить использование памяти
- ✅ Использовать Web Workers для изоляции выполнения
- ✅ Реализовать ограничения на использование системных функций (например, файловая система, сеть)

### 3. Тестирование кода в браузере
**Проблема:**
- Не описано, как именно будут реализованы тесты
- Нужно обеспечить безопасное выполнение тестов

**Рекомендации:**
- ✅ Использовать Pyodide для выполнения и unittest/pytest
- ✅ Изолировать выполнение тестов от основного кода
- ✅ Парсить вывод тестов для отображения результатов в UI
- ✅ Поддержка как юнит-тестов, так и интеграционных тестов

### 4. Структура базы данных
**Проблема:**
- Отсутствует описание схемы БД
- Неясно, как хранятся модули, задания, прогресс, достижения

**Рекомендации:**
- ✅ Добавить ER-диаграмму или описание таблиц:
  - `users` (профиль пользователя Appwrite Auth)
  - `modules` (id, title, description, order, level, topic)
  - `lessons` (id, module_id, title, theory_content, order)
  - `tasks` (id, lesson_id, title, description, starter_code, test_cases)
  - `user_progress` (user_id, lesson_id, status, xp_earned, completed_at)
  - `achievements` (id, title, description, icon, xp_reward)
  - `user_achievements` (user_id, achievement_id, earned_at)
  - `leaderboard_cache` (опционально, для оптимизации)

### 5. Система XP и достижений
**Проблема:**
- Не описана логика начисления XP
- Неясно, как работают достижения

**Рекомендации:**
- ✅ Определить формулы начисления XP:
  - Решение задачи с первой попытки: X XP
  - Решение со второй попытки: X * 0.7 XP
  - Использование AI-подсказки: X * 0.5 XP
- ✅ Добавить типы достижений:
  - Первая задача решена
  - Решено 10 задач без подсказок
  - Завершен модуль
  - Неделя подряд активность
- ✅ Добавить уровни пользователя (на основе накопленного XP)

**Проблемы:**
- Hugging Face Inference API имеет rate limits на бесплатном уровне
- Качество ответов может быть нестабильным

**Рекомендации:**
- ✅ Добавить rate limiting на стороне приложения
- ✅ Кэшировать частые запросы
- ✅ Fallback на предзаготовленные подсказки, если API недоступен
- ✅ A/B тестирование промтов для улучшения качества
- ✅ Модерация сгенерированного контента (админ должен проверять)

### 10. Версионирование и миграции
